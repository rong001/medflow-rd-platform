# MedFlow

医疗器械研发协同平台，围绕血压监测、血糖监测及平台预研，连接产品战略、设计控制、质量验证与制造交付。

## 产品体验

- 5 个业务分类、18 个独立模块。
- 研发攻关、转产交付、上市改进三个独立业务空间，每套都有完整初始业务记录。
- 精密紫、雾白精密、深海科技三种可随时切换的界面主题。三个主题均可使用全部业务空间。
- 每套数据包含 4 个产品项目、16 条需求、16 项验证、5 条风险、24 份文档、64 条业务事项，以及变更、人员和操作记录。
- 可新建项目、需求、风险、设计事项和质量问题；记录验证、评审风险、修订文档、推进变更和完成转产。
- 全局搜索、状态筛选、关联详情、任务看板、经营周报、追溯矩阵和资料导出。

## 业务链路

`产品需求 → 设计输出 → 风险控制 → 验证与确认 → 工程变更 → 受控文件 → 制造交接 → 阶段放行`

验证未通过时不能接受关联风险；文档未批准时不能完成制造交接；设计输出、验证、风险、评审或制造事项未满足条件时，阶段门会给出阻塞原因。

新增需求会创建设计任务、验证任务并重新开启相关文档与交接；文件修订会重新开启评审和制造交接；工程变更会重新开启验证、风险、文件和交接记录。质量问题可以发起工程变更，变更关闭后再完成独立的效果确认。

## 本地运行

使用 Node.js 24 与 pnpm 11.19.0。

```sh
pnpm install --frozen-lockfile
pnpm dev:pages
```

验证与构建：

```sh
pnpm typecheck
pnpm test
pnpm build:pages
pnpm preview:pages
```

## GitHub Pages

`.github/workflows/pages.yml` 会在 `main` 更新时执行类型检查、业务回归、静态构建及部署。

仓库 Pages 设置使用 **GitHub Actions**。项目采用 hash 路由与相对资源路径，可在仓库子路径直接运行、刷新和分享页面。站点地址由 GitHub Pages 设置生成，后续发布使用同一个地址；持续可用依赖仓库、账户和 Pages 服务保持启用。

Pages 版本把业务数据保存在当前浏览器的 IndexedDB，三个空间互相隔离，刷新和切换后保留修改。数据不会自动同步到其他设备；清除浏览器站点数据也会清除本机修改。可在“分析与报告”导出完整数据归档，左下角恢复按钮仅恢复当前空间。

源码同时保留原有 Vinext / Cloudflare Workers + D1 服务端入口（`pnpm dev`、`pnpm build`）。该入口使用独立会话、场景隔离、原子版本检查及同源提交约束。GitHub Pages 不运行这一服务端入口。

原托管账户的 `.openai/hosting.json` 配置留在本地，不包含在公开源码中。GitHub Pages 构建不需要该文件；重新使用原托管服务时需单独配置账户绑定。

## 交付范围

这是用于面试展示和产品方案验证的交互版本。所有项目、人员、供应商、文件摘要和业务数据均为合成数据，不代表招聘企业的真实记录。界面采用正式产品文案，不包含环境横幅或 mock 标签。

本版本未接入企业身份认证、真实电子签名、附件存储、跨设备协同、权限审计及实际医疗器械质量体系。业务中的“批准”“放行”只改变当前工作空间记录，不构成真实生产放行、注册批准或合规认证。正式商业化需根据实际企业流程完成后端、身份权限、质量体系验证和安全设计。

JD 未披露企业名称，无法可靠确认招聘主体。产品范围依据 JD 职责与医疗器械研发通用流程设计，调研依据见 [行业与需求研判](docs/industry-research.md)。
