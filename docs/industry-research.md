# 需求研判与设计依据

调研基准日：2026-09-26。招聘材料只提供“深圳某中型医疗器械公司”，无法据此唯一确定企业。以下是基于 JD 的产品需求推断，而非企业内部事实。

## JD 与系统能力对应

| 职责 | 推断出的管理需求 | 系统入口 |
|---|---|---|
| 产品及技术战略、年度技术目标 | 产品组合、技术路线、季度目标 | 战略与调研、项目组合 |
| 主导研发、控制技术路线与交付 | 需求基线、设计输出、阶段评审 | 产品需求、设计开发、设计评审 |
| 全球法规与质量体系落地 | 需求、风险、验证与文件间可追溯 | 需求追溯、风险管理、文档中心 |
| 产品主记录、工艺转产及生命周期支持 | 受控资料和制造准备分别管理 | DMR 产品主记录、转产与交付 |
| 团队、预算及跨部门协调 | 人员负荷、预算执行、统一待办 | 资源与预算、研发总览 |
| 量产问题与技术支持 | 问题、变更、复测、效果确认 | 质量问题、工程变更、验证与确认 |

## 研究结论

1. 总监工作台应暴露阻碍项目推进的证据缺口，并让负责人从总览直接进入问题记录。
2. 验证与确认应区分：前者核对设计输出与设计输入，后者关注预期用途与目标用户场景。[FDA 设计开发培训](https://www.fda.gov/media/189041/download)
3. 风险管理贯穿产品生命周期，需连接控制措施、验证证据与残余风险评审。[ISO 14971:2019](https://www.iso.org/standard/72704.html)
4. 医疗器械软件生命周期需管理配置、验证和变更；软件活动不等同于整机最终确认及放行。[IEC 62304](https://webstore.iec.ch/en/publication/22794)
5. 制造转移需同时确认文件、工艺、设备、人员和执行能力，文档齐套率不能等同于量产就绪。[FDA 设计开发培训](https://www.fda.gov/media/189041/download)
6. FDA QMSR 于 2026-02-02 生效。界面保留 JD 使用的 DMR 业务名称，但不将旧版独立 DMR/DHF/DHR 条款表述为现行 QMSR 条文。[FDA 最终规则](https://www.fda.gov/media/177022/download)
7. 中国新版医疗器械生产质量管理规范将于 2026-11-01 实施，调研时仍处于实施前过渡阶段。实际项目应由法规负责人按目标市场和产品范围确认适用依据。[中国政府网转载公告](https://app.www.gov.cn/govdata/gov/202511/06/539701/article.html)

## 三套业务空间

研发攻关侧重低电量中止、记录完整性、需求追溯及风险控制；转产交付侧重文件批准、关键物料、工装、培训和交接；上市改进侧重现场反馈、变更实施与回归证据。血压和血糖产品的技术内容分别配置，不假定二者适用相同的技术指标或注册路径。
