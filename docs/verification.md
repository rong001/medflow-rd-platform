# MedFlow v2 验收记录

日期：2026-09-27。范围：交互产品、三套业务基线与 GitHub Pages 静态发布构建。

## 视觉设计

采用 Product Design 流程生成精密紫、雾白精密、深海科技三个方向，并将其实现为产品内可选主题。主方向使用浅紫侧栏、连续白色工作区、扁平指标带、业务表格和右侧事项栏；品牌标志独立设计为靛蓝与青蓝的折带 M。

最终以 1488 × 1056 的浏览器视口，将精密紫设计参考与实际生产构建截图放在同一轮输入中比对。两轮调整增加辅助文字可读性、压缩导航行距和表格间距，使 18 项导航及四个阶段进度行在该桌面尺寸内可见。另检查 1280 × 720 与 390 × 844 布局；窄屏侧栏可独立滚动，表格允许横向查看，表单保持可操作。

保留的设计差异：实际指标由记录计算；采用真实阶段状态图替代参考图中的日历甘特图；右侧栏从指标带下方开始；文案、人数与日期遵循业务数据。此次交付是以参考方向实现完整产品，不是像素级临摹。

三种主题已实际切换；最终精密紫生产构建的搜索、空列表和移动菜单均完成浏览器操作检查。最终生产页控制台未发现错误或警告。

## 业务检查

- 18 个菜单均可打开对应模块。
- 浏览器实测 BP-A2 验证复测、风险接受、变更验证关闭、文件批准、物料确认、制造交接、设计评审和最终阶段放行；未批准文件会阻止制造交接。
- 刷新后保留修改；三个业务空间互相隔离。手机端创建项目，在另一个空间不可见，返回原空间仍存在。恢复初始基线仅作用于当前空间。
- 全局检索“低电量”返回验证、风险、设计事项和质量问题，点击验证结果进入相应模块及记录详情。
- 初始研发空间选择“已转产”正确显示空状态；选择全部项目恢复四个项目。
- 手机菜单能展开、显示全部分类并通过关闭按钮收起。
- 纯业务逻辑回归共 240 项断言通过，包括新项目完整链路、关联完整性、失败验证拦截、风险接受、质量问题关联变更、文件修订重新开启评审、空间重置隔离和阶段门阻塞。
